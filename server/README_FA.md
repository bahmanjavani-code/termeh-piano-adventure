# سرور امن پرداخت ترمه — مرحله ۲ (فقط کد زیرساخت، هنوز مستقر نشده)

**وضعیت: در حال ساخت. هرگز هنوز وجه دریافت نکنید یا درخواست انتشار به بازار ندهید.**

## آنچه تا امروز آماده است

- برنامهٔ اندروید از کتابخانهٔ رسمی Poolakey استفاده می‌کند، کلید عمومی RSA بازار را از GitHub Actions در زمان ساخت دریافت می‌کند و **فقط در بخش والدین** خریدهای فعلی را بررسی می‌کند.
- `server/secure-activation-core.cjs` یک هستهٔ مستقل و **آفلاین قابل آزمایش** برای مرحلهٔ فعال‌سازی است. این هسته بدون هر سه سرویس قابل‌اعتماد خارجی، با خطای امن متوقف می‌شود:
  1. `verifyWithBazaar`: تماس واقعی سرور با API معتبر **فعلی** بازار برای تأیید توکن خرید و وضعیت خرید/استرداد؛ خروجی ساختاریافتهٔ آن باید حتماً `verified=true`، `packageName=com.termeh.piano`، `productId=termeh_premium_lifetime` و `purchaseState=PURCHASED` باشد. **هیچ‌یک از این فیلدها نباید از بدنهٔ درخواست دستگاه گرفته شود**.
  2. `registerDevice`: کنترل وضعیت خرید و نگاشتِ هش توکن به هش کلید دستگاه به‌صورت اتمیک، محدودیت نرخ، سوءاستفاده و سیاست منطقی انتقال/بازیابی روی گوشی جدید. توکن کامل هرگز در گزارش‌ها ثبت نشود. اگر کنترل‌ها آماده نباشد، فعال‌سازی ممنوع است.
  3. `loadPack`: خواندن بستهٔ AES-256-GCM و کلید ۳۲بایتی آن از فضای **خصوصی** سرور. کلید نباید در GitHub Pages، APK یا مخزن عمومی ذخیره شود.
- بستهٔ خصوصی، قبل از بسته‌بندی برای دستگاه، دوباره در سرور رمزگشایی آزمایشی و اصالت‌سنجی می‌شود؛ بستهٔ تغییرکرده رد می‌شود.
- کلید AES محتوا با کلید عمومی RSA **همان دستگاه** با OAEP-SHA256 بسته‌بندی می‌شود؛ کلید خصوصی دستگاه باید در Android Keystore غیرقابل‌خروج باشد. نسخهٔ فعلی اندروید هنوز اتصال عملی Keystore و تحویل درس‌ها را ندارد.
- `tests/secure-activation.test.cjs` حالت‌های قبول، بازپرداخت، محصول و بستهٔ اشتباه، سرور ناموفق، حملهٔ بستهٔ دستکاری‌شده و کلید دستگاهٔ دیگر را **با دادهٔ جعلی و بدون خرید واقعی** آزمایش می‌کند.

## چه چیزی هنوز وجود ندارد؟

**نه آدرس سرور HTTPS داریم، نه سرویس فعال، نه کلید خصوصی محتوای تولید، نه تماس واقعی با API بازار، نه خرید/بازگرداندن فعال، نه دریافت بستهٔ پولی روی اندروید.**
بنابراین حتی عبور تمام آزمون‌های CI به معنای آمادهٔ فروش بودن نیست.

## وابستگی بیرونی — انتخاب زیرساخت

برای ادامه، مالک باید یک سرویس قابل مدیریت HTTPS برای برنامه انتخاب کند (مثلاً سرویس سازگار با Node.js، یا Worker با آداپتور متناسب).
**GitHub Pages فقط صفحهٔ ایستا می‌دهد و محل مناسبی برای نگهداری اعتبار خصوصی و بررسی رسید پرداخت نیست.**

به علت تغییر مستندات/API بازار در سال ۱۴۰۳، مسیر و روش احراز هویت API **نباید حدس زده شود**. قبل از تکمیل `verifyWithBazaar` باید مستند رسمی نسخهٔ فعلی و بخش «API» پیشخان شخصاً بررسی شود. کلید RSA عمومی **جایگزین توکن خصوصی API** نیست.

پیش از استقرار عمومی: اتصال رمزدار، مدیریت امن اسرار، نگهداری و بازیابی حداقلی اطلاعات، API سخت‌گیرانه و محدودیت نرخ، ضدتکرار درخواست، پاک‌کردن دادهٔ پرداخت از گزارش‌ها، تایید واقعی نمونه خرید رسمی بازار، کنترل استرداد وجه، حالت خطای شبکه و بازیابی در گوشی تازه باید آزمایش شود.

## دستور تست در محیط توسعه

```sh
node tests/secure-activation.test.cjs
```

این آزمون از `verifyWithBazaar` **جعلی داخل تست** استفاده می‌کند. هیچ تابع آزمایشی یا کلید ثابت تست نباید وارد سرور تولید شود.
